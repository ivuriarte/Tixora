1. Development Principles

  • Additive-only schema changes: Every Prisma migration adds fields or tables. No existing columns dropped or renamed.
  • Feature flags before removal: PayMongo flow is hidden via NEXT_PUBLIC_ENABLE_ONLINE_PAYMENT flag — not deleted. Deletion deferred to post-MVP.
  • Test-first on new modules: Write at least the happy-path unit test before or alongside new service methods.
  • No deploy without CPD: The user must say "CPD" (Commit, Push, Deploy) to trigger any git commit, push, or Vercel deployment. Development work can proceed without CPD.
  • Cybersecurity checkpoint before CPD: Run security test suite (S-01 to S-18) and fix all findings before calling a phase complete.

2. Standard Lifecycle

This lifecycle applies to every phase:

  1. DEVELOP — Implement changes per phase task list
  2. QA — Run unit + integration tests. Fix failures.
  3. PERFORMANCE CHECK — Verify no slow queries (no N+1). Spot check critical endpoints with <200ms target.
  4. CYBERSECURITY AUDIT — Run applicable security tests from the test plan for this phase.
  5. FIX FINDINGS — Fix all security findings before proceeding.
  6. RE-TEST — Repeat until clean.
  7. INFORM USER — Report phase complete to user with summary.
  8. AWAIT CPD — User says "CPD" → then commit, push, deploy.
HARD RULE: Never run git commit, git push, or trigger a Vercel deployment without explicit "CPD" from the user. Code can be written and tested locally without CPD.

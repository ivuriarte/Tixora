1. System Overview

Axon Tickets is a Turborepo monorepo containing two deployable applications and two shared packages. All deployments target Vercel (serverless). The database is Neon (PostgreSQL, serverless), accessed via Prisma ORM. Redis (Upstash) is used for session management, rate limiting, and idempotency.

MONOREPO ROOT ├── apps/ │ ├── api/ → NestJS REST API (Vercel Serverless Functions via @vercel/ncc) │ └── web/ → Next.js 14 App Router (Vercel Edge + SSR) └── packages/ ├── types/ → Shared TypeScript interfaces (@axon-tickets/types) └── utils/ → Shared utility functions (@axon-tickets/utils) External Services ├── Neon PostgreSQL → Primary database (serverless, pooled connections) ├── Upstash Redis → Sessions, rate limiting, idempotency, OTP protection ├── Cloudinary → Event images (public) + Payment proofs (private) └── Resend → Transactional email delivery

7. API Endpoint Specification

7.1 Public Registration Endpoints (no auth)

MethodPathDescription
POST/api/v1/registrationsCreate solo or group registration. Rate: 10/min/IP.
POST/api/v1/registrations/lookupAuthenticate attendee: email + referenceNumber → returns JWT session. Rate: 10/min/IP.
GET/api/v1/registrations/:idGet registration detail. Auth: attendee session JWT or admin JWT.

7.2 Attendee (reference session) Endpoints

MethodPathDescription
POST/api/v1/registrations/:id/proofUpload proof of payment. Auth: attendee session. Multipart/form-data.
GET/api/v1/registrations/:id/statusGet current registration status and proof history.

MethodPathDescription
GET/api/v1/admin/verificationsList registrations for verification queue. Query: ?status=submitted&eventId=&page=1&limit=20

11. Cloudinary Strategy

Asset TypeFolderUpload TypeAccess
Event images (banner)axon-tickets/events/Authenticated upload, public deliveryDirect Cloudinary URL (public)
Payment QR imagesaxon-tickets/payment-qr/[eventId]/Authenticated upload, public deliveryDirect URL (attendee-facing — just an image)
Payment proof filesaxon-tickets/proofs/[registrationId]/Authenticated upload, privateServer-generated signed URL (30-min expiry, admin only)
Security Rule: Payment proof Cloudinary public IDs are never stored as direct URLs that could be shared. Only the publicId is stored in the database. The UploadService.getSignedProofUrl() method generates a time-limited URL on demand for admin use only.

12. Email Service Architecture

Email Types and Triggers

EmailTriggerRecipientContains
Registration ConfirmationPOST /registrations successLead registrantReference number, attendee names, payment instructions link

Rejection NoticeAdmin rejects registrationLead registrantEvent name, rejection reason, re-upload link
Cancellation NoticeAuto-cancellation cronLead registrantEvent name, cancellation reason, link to re-register if tier open
QR ResendAdmin clicks Resend QREach individual attendeeSame as QR Delivery

Resend Configuration

  • SDK: resend npm package v2
  • From address: hello@axontickets.ph (events) / noreply@axontickets.ph (system notifications)
  • Templates: HTML string templates (Handlebars or JSX-based via React Email library)
  • Retry: Resend handles delivery retries (3 attempts). Failures logged as structured error. Admin can trigger manual resend.
  • Free tier: 3,000 emails/month (sufficient for MVP events of 300–450 attendees + confirmation emails)

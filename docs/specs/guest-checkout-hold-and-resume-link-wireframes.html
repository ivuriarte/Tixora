  • Which banner shows: the banner appears only when the registration has a hold deadline. Only add-on-free guest checkouts get one, so this banner can never appear together with the add-on stock banner (add-on registrations have no deadline; the API refuses add-ons on a guest checkout intent).
  • Screen readers: the banner sentence is the only live-region text and does not tick. The ticking digits are aria-hidden with a static text equivalent. A separate polite announcement fires only at 10, 5 and 1 minute left (WCAG 2.2.1). CountdownTimer is wrapped, not edited.
  • Urgency is never colour-only: every state carries words ("Only 4:32 left"). The timer's own colour (amber, red under 1 minute) is decoration.
  • Deadline vs server: the displayed deadline is a promise to the customer. The server may keep the seats up to about 5 minutes longer, never shorter; a proof uploaded in that window is accepted.
  • Separation of actions: "Cancel reservation" sits in its own row, red text, away from "I will pay later" so it cannot be mis-tapped.
  • Logged-in users keep today's page; they have no deadline and so no banner.

  • Hold limit: shown at the ticket step where the hold is created, as an alert on the existing error state. Shared mobile connections are common; the message tells people what to do, not just that they were blocked.
  • Expired: also shown when proof upload hits a cancelled registration (replaces the raw "Cannot upload proof" error). No error state needed: its only action is navigation.
  • Opened elsewhere: resuming rotates the access token, so the previous tab gets this state instead of "Payment screen unavailable".

  • A network or server error shows the retry state and never the "invalid link" state, so a patchy phone connection doesn't tell people to start over and lose their seats. Only a clear 404 means invalid.
  • The token is read from the URL fragment in the browser and the fragment is removed from the address bar immediately. The page is excluded from the Meta Pixel and from funnel URL capture (see screen 7).
  • Focus moves to the heading of whichever state is shown.

PAGE RULES

Declarations for the Frontend gate

ItemDeclaration
Resume page URL/events/[slug]/register/resume (token only in the URL fragment)
MetadataTitle "Resuming your reservation | Axon Tickets"; robots noindex, nofollow; referrer policy no-referrer; not in the sitemap. No public facts to render (not a public page).
TrackersExcluded from the Meta Pixel (route exclusion). Internal funnel and Sentry URLs are sent without the fragment.
Extended holdsMax 2 extended (24-hour) holds per IP per event per day (configurable). Beyond that the email is still sent but the hold stays at 60 minutes and the page shows the real deadline.
Banner time formatUnder 60 min: 42:10. 60 to 120 min: 1 hr 12 min. Over 120 min: the deadline date. Screen-reader announcements at 10, 5 and 1 minute.
Expired vs elsewhereOn a 404 for the reservation: "expired" screen if the locally known deadline has passed, else the neutral "opened on another device" wording.
Cap default5 unpaid guest holds per IP per event per hour (configurable).
Date formatOne helper: weekday, month, day, year, time with a dot separator, always Asia/Manila. Wrap on narrow phones; never drop the year.
FocusMoves to the new content's heading or field after every in-place swap (pay-later card, expired, cancelled, resume states).
Funnel review (design rule 6)No step moved or removed. Conversion-relevant changes to record in the ledger: guest hold shortened 24 h → 60 min, "I will pay later" now opens a card first, raw errors replaced by "Start again". New funnel events are additive.

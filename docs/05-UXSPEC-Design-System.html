3. Design System — Spacing & Layout

  • Base unit: 4px. All spacing is multiples of 4.
  • Container max-width: 1200px (events list), 800px (registration forms), 1100px (admin dashboard)
  • Card border-radius: 8px (standard), 12px (featured/hero cards)
  • Input border-radius: 6px
  • Button border-radius: 6px
  • Shadow (card): 0 1px 4px rgba(0,0,0,0.08)
  • Shadow (modal): 0 8px 32px rgba(0,0,0,0.18)

Grid System

  • Mobile: single column (full width), 16px horizontal padding
  • Tablet (768px+): 2-column grid where applicable, 24px gutter
  • Desktop (1024px+): 3-column for event cards, side-by-side for form + summary panel

  • Loading state: spinner replaces icon/text, button disabled. Spinner color: white on primary, #EA6C00 on secondary.
  • Focus ring: outline: 2px solid #EA6C00; outline-offset: 2px (WCAG AA)

Form Inputs

  • Height: 40px. Padding: 8px 12px.
  • Border: 1px solid #dde3ec. Radius: 6px.
  • Focus: border-color #EA6C00, box-shadow 0 0 0 3px rgba(234,108,0,0.15)
  • Error state: border-color #dc2626. Error message below in #dc2626, 12px, appears only after first submit attempt or on blur.
  • Helper text: below field, #64748b, 12px.
  • Required indicator: asterisk (*) in #dc2626 after label text.

Status Badges

  • Pill shape: border-radius 100px. Padding: 3px 10px. Font: 11px uppercase, weight 600.
  • Colors per registration status from §1.
  • Always text + small circle dot (left of text, 6px diameter, same color as text).

Cards

  • Background: white. Border: 1px solid #dde3ec. Radius: 8px. Shadow: 0 1px 4px rgba(0,0,0,0.08).
  • Padding: 20px (mobile), 24px (desktop).
  • Hover: slight shadow increase for clickable cards.
  • Event card: image (16:9 ratio, object-cover), tier badge overlay, title, date/time, venue.

Navigation

  • Public nav: White background, logo left, "Find My Registration" link right, sticky on scroll.
  • Admin nav: Left sidebar, #1A3A5C background, white text. Active item: left border #EA6C00 + slightly lighter background. Items: Dashboard, Events, Verification Queue, Orders (legacy), Attendees, Check-in, Audit Log.
  • Mobile nav: Bottom tab bar for attendee flows (Home, My Registration). Admin: hamburger → slide-in drawer.

5. User Flows

Flow 1 — Solo Registration

Home (/) → Event Detail (/events/[slug]) → Click "Register Now" → Registration Form (/events/[slug]/register) [Enter: first/last name, email, contact, optional fields] [Select tier → shows price + remaining capacity] [hCaptcha verification] [Click "Continue"] → Confirmation Screen (/events/[slug]/register/confirm/[regId]) [Shows: reference number, summary, payment instructions, payment QR image] [Click "Upload Payment Proof"] → Payment Screen (/events/[slug]/payment/[regId]) [Drag/drop or browse: JPEG, PNG, or PDF, max 5MB] [Click "Submit Proof"] → Status Page (/my-registration/[referenceNumber]) [Status: SUBMITTED — "Payment proof received. We'll email you once verified."] [Attendee waits for organizer email] → Email received: QR delivery (if approved) or rejection notice (if rejected)

Flow 2 — Group Registration

Event Detail → Click "Register as Group" → Registration Form (GROUP mode) [Lead attendee fields at top] [+ Add Attendee button → appears up to maxGroupSize times] [Each attendee row: first name, last name, email, contact] [Total price = tier price × attendee count — shown live] [hCaptcha] [Click "Continue"] → Confirmation Screen [Shows: reference number, full attendee list, payment total] → Payment Screen (same as solo — single proof upload covers the group) → Status Page (same experience)

Flow 3 — Find My Registration

Nav: "Find My Registration" → Lookup Page (/my-registration) [Enter: email address + reference number (e.g., AXN-20260619-0042)] [Click "Find Registration"] → Status Page (/my-registration/[referenceNumber]) [Shows current status, attendee list, event summary] [If REJECTED: re-upload proof button] [If APPROVED: "Your QR code has been sent to [email]"]

Flow 4 — Organizer Verification

Admin: Verification Queue (/admin/verifications) [Filter by: event, status. Sort by: date submitted] [Table row: reference, attendee name(s), tier, amount, date, status badge] [Click row → detail page] → Verification Detail (/admin/verifications/[id]) [Left: registration info — attendee list, tier, reference number] [Right: proof image preview (signed URL, loaded inline)] [Below image: "Approve" (green) and "Reject" (red) buttons] [Reject → modal: select reason (preset list) + optional note → Confirm] → Approve → status changes to APPROVED → QR emails sent → Reject → status changes to REJECTED → rejection email sent → attendee can re-upload

Flow 5 — QR Check-in (Camera)

Admin: Check-in (/admin/checkin) [Large camera viewfinder area — ZXing auto-scans] [On scan: API call → success toast (name + tier) OR error toast] → Success: "[Name] — [Tier] — ✓ Checked in" → Already scanned: "Already checked in at [time]" → Invalid token: "QR code not recognized" [Manual lookup: search box below scanner → search by name/email → click row to check in]

6. Screen Specifications — Attendee Side

Home Page (/)

  • Hero section: platform logo + tagline. Subtle background using #1A3A5C gradient.
  • Event cards grid: 3-col desktop, 2-col tablet, 1-col mobile.
  • Card shows: event image, event name, date, venue, "Register Now" button, capacity badge ("45 spots left").
  • Filters: date range, city (if multiple events).
  • Empty state: "No upcoming events. Check back soon."

Event Detail Page (/events/[slug])

  • Full-width event banner image (top). Event title + date + venue below.
  • Left column (2/3 width): description, speaker/program section, venue map iframe (Google Maps embed or link).
  • Right column (1/3 width): Sticky registration panel. Tier selection (price + remaining slots). "Register Now" CTA.
  • If event is full: disabled button "Registration Closed".
  • If tier is full: tier shows "Sold Out" badge, cannot be selected.

Registration Form (/events/[slug]/register)

  • Step indicator at top: 1. Fill Form → 2. Payment → 3. Done.
  • Section 1: "Lead Attendee" — required fields with asterisks.
  • Section 2 (group only): "Additional Attendees" — card per attendee with fields + Remove button. "Add Attendee" button below.
  • Section 3: Order Summary (read-only: tier name, count, price per, total). Fixed to bottom on mobile.
  • hCaptcha widget above submit button.
  • Submit button: "Continue to Payment →".
  • Back button: returns to event detail.

Confirmation Screen (/events/[slug]/register/confirm/[regId])

  • Green checkmark icon + "Registration Submitted!" heading.
  • Reference number prominently displayed in large monospace font, with copy-to-clipboard button.
  • Summary box: event name, tier, attendee count, total amount.
  • Payment instructions panel: organizer's text instructions + QR code image(s) below.
  • CTA: "Upload Proof of Payment →" (primary button).
  • Note: "Save your reference number. You'll need it to check your registration status."
  • Email note: "A confirmation email has been sent to [email]."

Payment Upload Screen (/events/[slug]/payment/[regId])

  • Step indicator: Step 2 active.
  • Upload zone: large dashed border box. "Drag and drop your proof here, or click to browse".
  • File format note: "Accepted: JPG, PNG, PDF. Max 5MB."
  • Preview: shows thumbnail (image) or PDF icon after file selected.
  • Remove file: × button on preview.
  • Submit button: "Submit Proof of Payment".
  • Loading state: spinner + "Uploading...".
  • On success: redirect to status page with SUBMITTED status.

Registration Status Page (/my-registration/[referenceNumber])

  • Top: status badge (large, prominent) + status description text.
  • Event summary card: event name, date, venue.
  • Attendee list: table (name, email, status per attendee if group).
  • Proof history: list of previous proof uploads with timestamp and status.
  • If REJECTED: rejection reason shown + "Re-upload Proof" button (primary).
  • If APPROVED: "Your QR tickets have been sent to [email]. Check your inbox."
  • If DRAFT: "Upload your proof of payment to complete registration." + Upload button.

7. Screen Specifications — Admin Side

Admin Login (/auth/login)

  • Centered card on #1A3A5C background. Logo + "Axon Tickets Admin" heading.
  • Email + password fields. hCaptcha. "Sign In" button.
  • Google OAuth button: "Continue with Google".
  • Error: "Invalid email or password." (generic — no enumeration).
  • Lockout: "Too many attempts. Try again in 15 minutes."

Admin Dashboard (/admin)

  • KPI cards (top row): Total Registrations, Pending Verification, Approved, Revenue (estimated from tier prices × approved count).
  • Verification Queue widget: top 5 most recent SUBMITTED registrations, with "View All" link.
  • Events table: upcoming events with registration progress bar (approved / capacity).
  • Recent audit log entries: last 10 actions.

Verification Queue (/admin/verifications)

  • Top filters: Event dropdown, Status filter (All / Submitted / Pending / Approved / Rejected), Date range picker.
  • Table columns: Reference Number, Attendee(s), Event + Tier, Amount, Submitted Date, Status.
  • Row click: open detail page.
  • Bulk select: checkboxes on rows + "Bulk Approve" button (activated when items selected).
  • Pagination: 20 per page.

Verification Detail (/admin/verifications/[id])

  • Two-column layout: left (registration info), right (proof image).
  • Left: reference number, event, tier, attendee list (table), amount, submission timestamp, status history.
  • Right: proof image rendered (from signed URL). If PDF: PDF icon + "View PDF" link (opens in new tab).
  • Action buttons at bottom: "Approve" (primary green) + "Reject" (outlined red) + "Resend QR" (ghost, shown only for APPROVED).
  • Reject → modal: rejection reason dropdown + optional note (max 300 chars).

Check-in Page (/admin/checkin)

  • Event selector: dropdown (only active events).
  • Camera viewfinder: large box (min 300px tall on mobile). Auto-scans using ZXing.
  • Result area: full-width toast below scanner. Green for success, red for error, orange for duplicate.
  • Stats: "Checked in: X / Y" counter updates in real time.
  • Manual section (below camera): search bar "Search by name or email". Results list with name, tier, status. Click "Check In" on a row.
  • Camera toggle: button to switch to rear/front camera.

9. Responsive Behavior

Breakpoints

NameMin WidthTarget
xs375pxSmall mobile (iPhone SE, budget Android)
sm480pxStandard mobile
md768pxTablet, large mobile
lg1024pxDesktop, laptop
xl1280pxLarge desktop

Mobile-First Rules

  • All layouts start as full-width single column on mobile, expand at md and lg.
  • Registration form: single column on mobile. On md: name fields split 50/50.
  • Admin sidebar: hidden on mobile, accessed via hamburger. On lg: always visible.
  • Verification detail: stacked on mobile (proof above, info below). Side-by-side on lg.
  • Event cards: 1-col mobile, 2-col md, 3-col lg.
  • All tables: horizontally scrollable on mobile with sticky first column.
  • Modals: full-screen slide-up on mobile, centered overlay on desktop (max-width 480px).
  • Camera scanner: full-width on mobile (most common use case for on-site check-in).
  • Minimum tap target: 44×44px (WCAG 2.5.5).

10. Accessibility Standards

Target: WCAG 2.1 Level AA

CriterionRequirementImplementation
Color contrast (text)4.5:1 minimum for body text#1a1a1a on white = 17.1:1 ✓. White on #EA6C00 = 3.4:1 (buttons use 14px+ bold — meets large text 3:1 minimum). White on #1A3A5C = 12:1 ✓.
Keyboard navigationAll interactive elements keyboard-accessibleTab order follows visual reading order. Modal traps focus while open. No focus traps elsewhere.
Focus indicatorsVisible focus ring on all interactive elements2px solid #EA6C00 outline with 2px offset (defined in globals.css)
Form labelsAll form fields have visible associated labels<label htmlFor=> on all inputs. No placeholder-only labelling.
Error messagesErrors announced to screen readersrole="alert" on error containers. aria-describedby linking field to error message.
ImagesAll informational images have alt textEvent images: descriptive alt. Payment QR images: "Payment QR code for [event name]". Status icons: alt="[status]".
Loading statesAnnounced to screen readersaria-busy="true" on loading containers. Spinner has role="status" aria-label="Loading...".
ModalsAccessible modal patternrole="dialog" aria-modal="true" aria-labelledby. Focus moves to modal on open. ESC closes. Focus returns to trigger on close.
Camera scannerAlternative for users who cannot use cameraManual lookup search bar is always visible below the camera view. Camera use is optional.
Touch target size44×44px minimumAll buttons, links, and interactive elements meet minimum tap target size.
Testing: Accessibility compliance to be verified with axe-core automated scan (integrated into Playwright E2E tests) + manual keyboard navigation audit before production release.
